# 數據分析：緊湊版與期間聯動

## 操作

- 保留總體、指定部門及指定個人；新增建立日期起／迄與事項來源篩選。
- 原八項指標縮成桌機單列，手機自動換行，保留所有數字。
- 要事與臨會／專題分類分開顯示件數、佔比及比例條；以該來源的事項數為分母，不以分類出現次數作分母。同一事項多選分類時，各分類各計一次，合計可超過 100%。
- 部門、人員、船舶排名與分類、曲線使用同一個已可見且篩選後的責任事項集合。可依完成率、責任件數、逾期件數或範圍內提出件數排序；同值並列。
- 點排名名稱可查看該對象的**責任事項**新增趨勢；再點一次或按「恢復全部」返回目前範圍。變更上方篩選會清除曲線焦點；同條件資料更新不清除篩選。
- 趨勢支援日／週／月及展開逐期件數，分成要事、臨會／專題兩條曲線。船舶沒有「提出者」意義，選提出件數排序時，船舶欄明確改按責任件數。
- 原船隊即時概況獨立標示並保留，不因歷史期間篩選而改寫目前關注度；統計口徑移至可展開的說明。

## 保留與邊界

- 沿用 `App` 傳入的資料及可見船舶範圍，不新增雲端讀取、修改、保存、角色或資料庫路徑。
- 原個人／部門責任判定、完成與逾期規則保留。船舶排名另使用既有逐船進度選擇器；會議關注程度不混入船舶目前關注度。
- 上方「提出率」保留原定義：所選人員的建立件數 ÷ 相同日期及來源條件下可見船隊的事項數，可能包含其非責任事項。排名中的「提出」限定目前責任集合，兩者在說明內明確區分。
- 分類佔比以各來源的事項數為分母；排名佔比以目前責任事項數為分母。跨部門／多人／跨船歸屬會重疊，不強制湊成 100%。
- 新增趨勢按 `createdAt` 的台北日期，不使用報告日或結案日，也不表示結案量。未設定起迄時用有效建立日期的完整範圍；週從星期一開始，首尾週只計選定日期內的事項。
- 缺期補零；日期無效／缺漏不編造事件日期。未設定日期條件時仍保留於總數並揭露曲線排除件數；有日期條件時不符合日期的事項不入集合。
- 超過 366 個時間點會提示縮短範圍或改用週／月，不暗中截斷。空範圍與反向日期明確提示，百分比不出現 NaN／Infinity。
- 未同步的獨立內控案件維持原下方船隊概況口徑，不混入上方責任事項曲線；此頁不取代「內控異常」的數據統計。

## 本機驗證

```sh
npm run test:data-analysis
npm run test:data-analysis-browser
npm run test:category-management
npm run test:meeting-vessel-progress
npm run test:attention-dimensions
npm run test:internal-control
VITE_BASE_PATH=/ship-dynamics-todo-system/ npm run build
git diff --check
```

計算與元件測試包含台北跨日、來源隔離、多分類去重、逐期補零、日期錯誤、並列排名及可見範圍。瀏覽器掛載實際 `DataAnalysisView` 與實際 CSS，使用隔離測試資料，檢查篩選／排序／趨勢互動、逐船完成、重新傳入資料後條件保留，以及 1280／820／390 寬度和數字可見性。

這些是本機真實元件 UI＋測試資料證據，不是正式雲端資料驗證。無需 SQL；Push 與部署由使用者控制。
