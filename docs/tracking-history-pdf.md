# 歷史記錄 PDF

## 操作與內容

岸端及船端：選取項目 →「查看歷史記錄」→「導出 PDF」→ 在瀏覽器列印視窗選擇「另存為 PDF」。預設 A4 直向，檔名包含船名、紀錄名稱及台北匯出時間。

每個項目依序列出申請單號與完整內容、緊湊目前資料表、補充說明與最新進度、狀態更新紀錄，最後為其他操作紀錄。各類歷史由新到舊排列，收合內容也完整匯出；同單號的不同項目不合併。長文自然跨頁，保留文字、框線與頁碼，不使用視窗截圖。

PDF 使用點擊當下視窗已讀取的保存資料，不另外宣稱即時雲端最新、不帶入未保存輸入、不補造缺少的歷史。缺少姓名不以內部 ID 代替；保留既有已刪除來源不匯出的規則。本入口只列所選紀錄，不改動既有清單 PDF／Excel 的自然月和篩選流程。

## 邊界

- 沿用 `canExport`，讀取／保存中、草稿、未知提交、匯入中不允許啟動。
- 不取得編輯鎖、不發送業務寫入，也不新增 SQL、套件或服務。
- 身份、船舶、選取範圍、資料或權限在等待字型期間變更即取消；不能藉往返身份或權限重用舊準備。
- 重複點擊只啟動一次；關閉、失敗、列印完成或取消均清理列印用節點、樣式、body class 及暫時檔名，保留原紀錄視窗與清單。

## 回歸入口

- `npm run test:tracking:history-pdf`：可見按鈕、資料轉換、順序、轉義、不顯示ID及刪除排除。
- `npm run test:tracking:history-pdf:browser`：原岸／船端入口＋本機原生 PostgreSQL、合成資料；真實導出流程、實際 PDF bytes、桌面／手機、無額外寫入／鎖。
- `npm run test:tracking:history-pdf:component`：明確標示的組件控制注入，驗等待字型／權限／身份／資料變動、未知 pending、失敗與重試、重複點擊、長篇歷史實際 PDF。

原生腳本沿用 `SHIP_QA_PG_BIN`、`SHIP_QA_PG_MODULE` 及 `QA_EVIDENCE_ROOT`；全部只連隔離 loopback。產出的 PDF、截圖和回條放證據目錄，不進版控。這些本機結果不是 hosted Supabase 或正式部署驗收。
